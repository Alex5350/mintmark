# Glossary

Terms used across Mintmark's documentation: collector terms first, engineering terms
second, plain English before precision.

| Term | In plain English | Precisely |
|---|---|---|
| Bullion | Precious metal in coin, round or bar form, valued mainly for its metal content rather than rarity. The "just the metal" end of collecting. | Items whose value tracks actual metal weight × spot price; the domain models `ItemForm` (Coin, Round, Bar, Ingot, JunkSilver, Scrap, Jewelry) alongside numismatic holdings. |
| Spot price | The live market price for one troy ounce of pure metal, the number every dealer quote starts from. | Per-troy-ounce price (XAU/XAG, USD base) polled by the Quartz job from metals.dev with gold-api.com failover; every `SpotPrice` row records its provider and source timestamp, and prices past freshness are flagged `stale` end to end ([ADR 0004](docs/adr/0004-price-providers.md)). |
| Troy ounce (ozt) | The weighing unit precious metals trade in. Heavier than the kitchen-scale ounce: about 31.1 grams, or roughly 1.1 ordinary ounces. | The domain `Weight` unit for metal; the single conversion site uses exactly 1 ozt = 31.1034768 g, unit-tested against known values. |
| Melt value | What the metal inside the coin is worth if you melted it down: the floor under any coin's value. | `actualMetalWeightTroyOz × quantity × spotPricePerTroyOz`, computed in `decimal` via the `Money` value object. Uses actual metal weight (ASW/AGW), never gross weight, so a 90% silver quarter and a 1 oz Eagle are valued correctly side by side ([docs/valuation.md](docs/valuation.md)). |
| Premium over spot / collectible value | What a coin sells for above melt because of scarcity, finish and condition, not just metal. Mintmark always shows both numbers together, with the inputs visible. | `collectibleEstimate = meltValue × Π(factors)` with every factor itemized and a rationale per line; a confidence band of ±(0.15 + 0.05 per applied factor beyond three) rides along, plus a method version (`rules-v1`) so history stays explainable ([ADR 0007](docs/adr/0007-valuation-rules-first.md)). |
| Mintage | How many of a coin were struck. Lower mintage usually means scarcer, and scarcity is one of the premium factors. | Catalog figure that must carry a source URL or stay null; feeds the mintage-tier premium factor (null → neutral, ≤5k → 3.00, up to >1M → 1.00). |
| Finish | How a coin's surface was struck: mirror-like proof, matte burnished, standard brilliant-uncirculated. A coin can be more than one thing at once (high relief and reverse proof). | Primary finish (BusinessStrike, BullionUncirculated, Proof, ReverseProof, Burnished, MatteProof, Unknown) plus independent attribute flags (HighRelief, Enhanced, Colorized, Antiqued, FirstStrike), because a flat enum would lose combinations ([ADR 0003](docs/adr/0003-finish-modeling.md)). |
| Series | A named coin family from one mint: American Silver Eagle, Libertad, Maple Leaf, Morgan Dollar. | The `Series` entity (mint + metal) that catalogs coin types; carries the demand-tier reference data used by valuation. |
| Mint mark | The small letter on a coin telling you which mint struck it (W for West Point, D for Denver, Mo for Mexico City). | A one-to-many attribute of `Mint`; mint mark is part of a coin type's identity (series × year × size × finish × mint mark). |
| Au:Ag ratio | How many ounces of silver one ounce of gold buys at current prices. Collectors watch it to judge which metal is relatively cheap. | A first-class derived series (gold spot ÷ silver spot) computed alongside daily closes and charted in both clients. |
| pgvector | A database add-on that lets Postgres remember what an image "looks like" mathematically, and find similar ones. | The PostgreSQL extension storing `CoinImage` embedding vectors; cosine similarity over these is one channel of hybrid catalog retrieval. |
| Vector similarity search | Asking the database: of everything in the catalog, which images are closest in appearance to this photograph? | Cosine similarity between the submitted image's embedding and catalog reference embeddings; combined in parallel with the other retrieval channels rather than trusted alone. |
| Perceptual hash (pHash) | A fingerprint of what an image looks like (not its raw bytes). Two photos of the same coin get nearly identical fingerprints, so they match even at different angles or sizes. | A DCT-based hash computed at preprocess; hamming distance against reference images is a retrieval channel, and identical re-uploads return the cached identification run (dedupe). |
| Expo | The toolkit that lets one JavaScript codebase build the actual iOS and Android apps, including camera and secure-storage access. | Expo SDK 57 / React Native 0.86 client with Expo Router, SecureStore, and SQLite; run and built via `apps/mobile`. |
| Offline queue | A to-do list on the phone for changes that could not reach the server yet (no signal in the safe room). They sync automatically when signal returns. | Durable SQLite `pending_mutations` with idempotency keys, retried with exponential backoff (30s to a 15-minute cap) on app focus and a timer; permanent 4xx failures dropped as unrecoverable; status always visible in Settings. |
| Idempotency key | A tag on a request that says "this is the same action as before", so a network retry cannot create the same holding twice. | A client-generated key carried on mutations; the server treats replays of the same key as one operation, which is what makes the offline queue safe. |
| Provenance / null semantics | Every figure says where it came from, or honestly admits it is unknown. The app never invents a number to fill a gap. | Catalog specs carry a `sourceUrl` or stay null (the seed validator rejects unsourced rows); spot rows record provider and timestamp; valuation rows record method version and the spot they derived from; vision-contract fields without visual evidence return null, never a guess. |
| Presigned URL | A temporary, expiring link to a private photo. Even if the link leaks, it stops working minutes later. | S3 presigned GET/PUT minted by the API (GETs expire in 15 minutes) against a private bucket; no image is ever served from a public location ([ADR 0006](docs/adr/0006-object-storage-s3-compatible.md)). |
| LTTB downsampling | Shrinking a huge price history to the few points that keep the chart's shape honest, instead of shipping every tick to the browser. | Largest-Triangle-Three-Buckets applied server-side for 3M-5Y/MAX point series; bucketed averages for 1D/1W/1M; raw ticks roll up to daily closes after 90 days. |
